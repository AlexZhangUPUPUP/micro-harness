# Task 来源状态

`TaskState` 保存独立于模型窗口的来源证据，作为后续结构化任务状态的基础。当前不包含调度、共享预算或任务生命周期，也不会自动推断任务已经完成。

## 边界

- 只接收用户原始文字和工具观察；助手回答、摘要、投影不作为来源证据。
- 每条包含递增顺序、来源、工具名称/调用 ID 和截断标记。顺序表示本实例的消息接收顺序；并发工具在窗口中按调用顺序加入，不代表外部操作实际完成的时间。
- 用户和工具各最多 32 条，每条最多 2048 字符。用户保留首条和最近 31 条；工具优先保留短观察，同长度淘汰较旧记录。省略数量明确累计，不能保证所有业务关键事实永久保留。
- 超长记录保留头尾并在中间明确标注省略；不复制图像 base64。完整原始事件仍由会话日志保存。
- 同调用 ID、名称、正文的重复工具观察不再加入；真实重复用户输入仍保留，支持撤销中途纠正。
- 快照独立克隆并校验结构。恢复旧窗口时只补充尚未出现的原始消息，兼容旧日志不能恢复从未持久化的信息。

## Context 集成

ContextManager 在原始工具输出截断前记录来源，压缩后的窗口可通过助手角色的 JSON 历史证据投影访问该状态。投影先预留完整请求成本，上限为正文预算 30% 且最多 900 个粗估 token，并让位于不可裁的最新输入和工具组；预算不足时可能不产生投影。

投影按时序引用记录，明确工具内容不属于用户授权或验收通过证明。它不改变权限系统，也不是 prompt injection 防护的安全边界。

`context.checkpoint.taskState` 是可选扩展：新快照恢复来源状态后只回放后缀；旧快照从同 Agent 原始事件及有效窗口重建。模型窗口和来源状态原子安装。仍使用原有事件协议和持久化文件，没有新数据库或运行时依赖。

混合旧窗口时，通过完整原始用户文本的哈希和工具调用 ID 排除已见来源，避免淘汰记录重新变成最新纠正。完整原始日志是该兼容路径的依据；若外部只保留部分检查点且原文已经丢失，不能保证识别所有来源，未来可增加稳定来源 ID。
