# 005：独立上下文管理模块

## 目标

将模型可见工作窗口统一交给 `packages/core/src/context/` 管理，借鉴 Codex 的日志与窗口分离、压缩 checkpoint、工具配对和 usage 校准机制，修复压缩预算与续聊不一致问题。

## 场景与验收

1. Harness 通过 ContextManager 添加、准备和恢复消息，不自行裁剪或通过数组 splice 恢复历史。
2. 保留 `context.ts`、`compact.ts` 与包级既有导出作为兼容入口；不改变 HTTP 响应格式。
3. 普通请求预算包括消息、工具定义、输出预留及安全余量；文本采用 UTF-8 粗估，真实 usage 可用于当前窗口校准，不能宣称是精确 tokenizer。
4. 首轮用户要求优先保留，但其工具历史允许压缩；最新用户要求与系统规则不静默截断，无法满足预算时在请求模型前明确失败。
5. 压缩是否应用取决于 changed，而不是消息净减少数；摘要自身有输入和输出上限，插入摘要后重新检查预算。
6. 摘要内容是结构化交接：目标与调整、约束、决策、进展、验证结果和后续步骤；摘要请求接受父取消信号，计入现有用量与费用事件。
7. 模型消息保留完整工具调用组，按 call ID 匹配；中断结果明确标记，不把孤儿结果发送给模型。
8. 版本化 checkpoint 保存实际消息窗口，恢复使用最近有效 checkpoint 和其后的同 Agent 事件；旧格式日志仍可恢复，未知版本 checkpoint 忽略并从原始事件重建。
9. 完整工具结果仍保存在审计事件中，恢复后缀沿用记录时截断策略；checkpoint 中的已截断正文不得再次截断。
10. 恢复使用当前系统规则，不恢复旧权限配置；用户图片随事件和 checkpoint 恢复。

## 范围

- 本次不实现远端 Responses compaction、后台异步压缩、向量检索或跨 Agent 共享费用账本。
- 不改变工具并发或权限行为，不升级依赖；保留上一批未提交修复。
- 新增或修改函数不超过 50 行，中文注释；只跑相关测试、类型检查和针对性离线验证。
