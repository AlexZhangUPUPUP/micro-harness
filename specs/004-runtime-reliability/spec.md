# 004：运行可靠性优化（阶段 1）

## 目标

修复索引重建重复累计用量、流式响应截断被视为成功，以及 GUI 会话切换时异步结果串扰的问题。保留现有 API、事件格式和权限预设。

## 场景与验收条件

1. 索引重建从事件重新计算 input、output、cost，包含子 Agent 用量；重复重建不得改变累计值。
2. 重建保留会话 ID、用户编辑的标题、创建时间等非累计元数据。
3. 流式响应需要明确的完成信号；提前 EOF、畸形数据和服务端错误不能作为正常完成返回。
4. 兼容现有 `[DONE]` 流和正常 finish_reason；长度截断与内容过滤需要报错，不执行不完整工具调用。
5. 取消、读取失败和回调异常向调用方传播；流读取器在正常与异常路径均释放。
6. 切换会话或卸载后，旧快照、旧事件和旧失败回调不得修改当前会话。
7. 当前会话快照加载失败时显示错误，不将上一会话历史合并进来；快照加载期间收到的当前会话事件保留并去重。
8. 权限和命令读取只接受当前会话或工作目录的结果；过期响应不覆盖新状态。

## 范围与边界

- 本批只实施优化计划阶段 1，不改变预算计费范围、工具并发、上下文压缩或持久化策略。
- 不增加运行时或测试依赖，不修改 API 响应契约。
- 流式兼容以已有 OpenAI-compatible 格式为准，不在输出开始后自动重放模型请求。
- 只运行相关回归测试、类型检查和 GUI 构建，不运行全量测试或真实模型请求。
