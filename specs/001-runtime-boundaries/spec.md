# 001：权限与子 Agent 隔离边界

## 目标

修复只读会话执行外部写工具，以及显式启用 worktree 后静默退回共享目录的问题。维持现有 API 响应格式与未启用隔离时的行为。

## 场景与验收条件

1. 只读会话：无论业务工具是否内置，声明 `mutating: true` 的工具都不得暴露给主 Agent 或子 Agent；模型强行请求该工具也不得执行。`task` 编排入口保留，但子 Agent 继承同一过滤后的业务工具集合。
2. 其他权限：维持现有 workspace/full/auto-review 工具与审批语义；只读的非联网外部工具仍可使用。
3. 网络限制：read-only/workspace 继续禁止声明 `network: true` 的工具。
4. 工作目录隔离：启用 worktree 时，非 Git 目录或创建失败必须返回可读的失败结果，不得请求模型或执行工具，也不得退回共享目录。
5. 资源释放：隔离准备失败后不泄漏并发名额；正常 worktree 路径仍可运行。
6. 配置切换：会话下一轮使用更新后的权限，主 Agent 与子 Agent 使用同一过滤结果。

## 范围与边界

- 权限依赖工具正确声明能力，不能替代操作系统级沙箱；MCP 适配器当前保守地将工具声明为可写。
- 本轮不解决符号链接、shell/MCP 取消、预算计量、事件协议或 workspace 下外部工具的目录约束。
- 已修复的 Web 主 Agent shell 传递不重复改动。
