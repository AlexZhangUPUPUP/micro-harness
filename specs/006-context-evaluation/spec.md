# 006：Context 专项评测

## 目标

用同一套可复核任务比较完整历史、drop-middle 与 summarize，验证上下文处理后约束、纠正、任务进展及重启状态是否仍可用。离线脚本只验证管线与可见性，真实模型小样本只作为冒烟证据。

## 场景与验收

1. 四类中文场景，每类三阶段；同一 seed/run 的三种模式共用原始历史与提问，期望值不进入最终提问或系统提示。
2. 固定模型、工具定义、温度、工具结果上限、输出预留和安全余量；完整历史用可容纳全部记录的大窗口并断言不发生裁剪。
3. 两种压缩模式实际发生至少两次有效压缩，summarize 必须实际采用摘要；没有触发的样本标 invalid，不计成功。
4. 确定性评分严格解析 JSON，逐字段检查随机事实、最新纠正、完成/待办和重复工具操作，不通过答案包含关键词判成功。
5. 重启通过磁盘 JSONL 和新 Harness 恢复，检查工作窗口逐项一致，再继续请求；工具结果乱序与图片引用作为恢复机制证据，不冒充视觉理解评测。
6. mock 仅根据模型请求中可见事实作答和摘要；删去事实应返回 unknown，替换事实应改变答案，不能访问场景期望值。
7. 从 Provider 包装层统计模型与摘要用量，usage 缺失不能作为零成本；报告调用覆盖率、费用估算、耗时、实际压缩策略和有效性。
8. 真实调用使用已有环境配置，限制总请求数、估算费用和单请求时间；报告不包含凭证，工具仅操作评测临时目录或无副作用替身。

## 范围与解释

- 不修改 Context 算法来迎合评测，不改变现有通用评测任务。
- 不使用 LLM 裁判评价这些可确定评分的任务。
- 真实模型先运行每场景每模式一次，样本不足以排名或证明统计显著提升。
- 跨 Agent 共享预算与 GUI 性能继续留待后续。
