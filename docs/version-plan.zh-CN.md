# micro-harness 版本功能计划

更新：2026-10-22。本文是后续版本的执行清单；版本号是计划，不代表已经发布，也不是发布日期承诺。

## 目标与当前基线

目标是一个可用于个人及小团队本地开发的 coding-agent harness：任务状态明确、长任务可持续、执行有边界、变更可审查、结果可验证、异常可恢复。

当前 `package.json` 为 `0.2.1`。已推送到 main 的最新提交为 `86d021b`，包含上下文模块化、运行时可靠性修复和上下文评测。独立 `task/` 来源证据、摘要选择和旧检查点恢复修复已在本地实现并验证，尚未提交、推送或发布；归入待整理的 v0.2.2。

已经存在的基础包括：Agent loop、流式响应、文件与 shell/web 工具、审批、独立子 Agent 限额、worktree、差异与合并、MCP/ACP、CLI、GUI、会话日志、SQLite 索引、可选 OS 沙箱、成本统计和评测。后文将这些能力的完善写作“补强”，不将它们当成全新功能。

真实上下文冒烟目前为完整历史 4/4、直接裁剪 4/4、摘要 3/4。剩余失败是模型在信息可见时混淆进度，不能据此声称可靠任务状态或通用编码成功率已经达标。来源账本也不等于完整任务生命周期。

### 范围与优先级

- **P0**：可能丢约束、重复副作用、覆盖用户修改、预算失控、停止无效或恢复错误；发现后优先修复，不等待所属版本。
- **P1**：交付验证、开发效率、互操作、可观测性、性能和可重复发布。
- **P2**：长期记忆、后台调度、更多平台和团队服务等扩展；有明确边界与进入条件。
- `[ ]` 表示未按本版本验收发布，即使部分代码已存在也不勾选。
- v0.2.2～v0.11 是 v1.0 候选范围；各版本满足自身门槛后才进入发布。可以拆补丁版，不为赶版本跳过门槛。
- 每版同时落实相关权限、持久化兼容、观测和测试，不能把这些工作全部延期到 v0.11。
- 保持现有 Bun/TypeScript、core/server/gui；以下目录是职责边界建议，实施时按真实依赖建立，不提前搭建空框架。
- 每个版本都必须同时更新后端契约和前端使用链路：后端提供事件/API/持久化/错误语义，前端提供状态展示/操作入口/失败反馈，二者都要有对应测试和 changelog 条目；只有一侧完成不算该版本完成。

### 每版交付包

| 交付项 | 后端必须提供 | 前端必须提供 |
| --- | --- | --- |
| 状态 | 稳定事件、状态转换、恢复语义 | 当前状态、转换中间态、失败/未知状态 |
| 操作 | API、权限校验、幂等和错误码 | 操作入口、确认、禁用条件和结果反馈 |
| 证据 | 日志、关联 ID、产物和验证记录 | 从结果追溯到事件、文件和验证 |
| 性能 | 分页、游标、背压和资源上限 | 增量渲染、虚拟列表和断线恢复 |
| 兼容 | 事件/API/存储迁移及版本说明 | 旧响应降级和升级提示 |
| 发布 | 定向测试、集成测试、支持范围 | GUI 构建、交互回归和无障碍检查 |

## v0.3：结构化任务状态与验收记录

模块：`packages/core/src/task/`；ContextManager 只消费状态快照，不承担业务状态机。

- [ ] TASK-01：定义 Task、Step、Constraint、Decision、Artifact、Verification 的稳定 ID、来源、状态和修订契约。
- [ ] TASK-02：目标、约束、计划、待办与当前有效决策独立保存；用户纠正通过修订/替代关系生效，旧值保留可追溯。
- [ ] TASK-03：提供显式状态更新入口；区分用户授权、模型建议、工具观察和系统确认；拒绝非法状态转换和过期修订写入。
- [ ] TASK-04：任务状态至少区分 queued、running、waiting_approval、interrupted、completed、failed、cancelled；步骤完成与任务完成分开。Task 跨执行尝试存在，Run 是一次执行；后续 RUN-10 只管理执行尝试，通过事件更新 Task，不建立第二套 Task 权威状态。
- [ ] TASK-05：每个验收条件记录 passed、failed、not_run 或 stale，并关联执行、日志和产物；未知值不能当作通过。
- [ ] TASK-06：验证绑定工作区内容版本/文件指纹、执行目录、命令、退出状态及工具调用；相关代码改动后失效，避免无条件重复已有效验证。
- [ ] TASK-07：用户称“评审完成”不能覆盖此前测试记录；助手声称“全部完成”不能直接把未满足条件的任务置为 completed。
- [ ] TASK-08：子任务返回结构化结果与证据引用；父任务独立验收，不能直接继承子 Agent 的成功声明。
- [ ] TASK-09：事件、检查点、恢复、fork 和任务状态修订一致；引入稳定来源 ID，补足不完整混合日志的来源识别边界。
- [ ] TASK-10：Context 按有效约束、当前目标、未完成步骤、相关证据、近期对话分配预算；展示状态冲突和内容省略，不默默挑选一个版本。
- [ ] TASK-11：来源账本区分原始证据与派生解释；长工具输出使用最小产物引用和按需读取，关键观察可显式固定、修订和释放。完整产物存储、保留与分页按 REC/UX 推进，不作为本版隐性前置条件。
- [ ] TASK-12：CLI/GUI 最小展示当前目标、状态、待办、验证与阻塞原因；不等 v0.10 才让状态可见。

验收：确定性测试覆盖纠正、撤销纠正、并发旧修订、验证失效、子任务假成功、两次以上压缩和恢复。新增未见自然语言场景，不依赖 STATE 等评测标签；原进度混淆场景按明确状态契约验证，不能通过改变评分口径掩盖失败。

## v0.4：共享预算、取消和运行生命周期

模块：按需要建立 `runtime/`；Harness 保留模型/工具循环，不堆入预算和树形生命周期细节。

- [ ] RUN-01：Session、Task、Run、Agent、ModelCall、ToolExecution 使用独立稳定身份，明确一次续聊与一次任务的关系。
- [ ] RUN-02：主 Agent、全部后代、摘要、自动修复和重试共享 RunBudget；可额外设置子任务局部上限，不能给每个子任务复制整份总预算。
- [ ] RUN-03：请求前预留成本/token/调用数/耗时额度，请求后按实际 usage 结算；并发预留原子化。
- [ ] RUN-04：缺失价格、usage、超时和迟到响应有明确策略；未知费用保留不确定状态或占用预留，不记作免费。区分逻辑调用与实际 HTTP 尝试。
- [ ] RUN-05：统一 RunScope 和取消传播，覆盖摘要、重试等待、审批、队列、子 Agent、MCP 和 shell；结束时清理监听、计时器和连接。
- [ ] RUN-06：取消后禁止迟到模型响应继续触发工具；子任务失败/超时按显式策略传播，不能出现父任务已结束而后台继续修改。
- [ ] RUN-07：分别配置连接、首包、流空闲、单调用、单工具和整个任务的超时；正常流式与非流式错误语义一致。
- [ ] RUN-08：退避、抖动、Retry-After、可重试错误分类和最大尝试数；取消优先，禁止无界重试；副作用重试交给 v0.5 的执行策略。
- [ ] RUN-09：重复工具调用、相同错误、无产物变化、循环委派和持续无进展检测；允许有界重规划，超限给出具体阻塞原因。
- [ ] RUN-10：queued/running/waiting/terminal 状态真实持久化；停止不再只等同于笼统 done；并发 send/resume/stop 有明确串行化语义。
- [ ] RUN-11：使用率、预算预留/实际/未知、剩余时间和停止原因可观测；摘要开销与主调用分开显示但不重复加总。
- [ ] RUN-12：统一可诊断错误类型、关联 ID 与可恢复建议；区分用户取消、预算停止、Provider 失败、工具失败和状态冲突。

验收：并发主/子/摘要调用竞争同一额度时不会重复发放预算；取消传播及资源释放有集成测试；shell 进程树强停依赖 v0.5。预算是执行策略保证，不把估算宣称为服务商账单硬上限。

## v0.5：工具调度、并发冲突与权限一致性

模块：按需要建立 `execution/` 与 `permissions/`；沿用现有 Tool、FileSystem、Sandbox 接缝。

- [ ] EXEC-01：工具声明读写资源、网络、风险、超时和幂等属性；默认保守处理未知外部工具，不能仅凭模型判断安全。
- [ ] EXEC-02：无冲突只读调用可并行；同一文件和相关目录的修改串行或使用版本校验；跨工具的 read-modify-write 纳入冲突检测。
- [ ] EXEC-03：编辑前校验读取版本/文件指纹，原子写入；冲突明确返回，不允许两个工具都宣称成功却静默覆盖一方修改。
- [ ] EXEC-04：工具参数按 schema 校验，限制路径、数据量、调用数量和输出；新建路径、符号链接和竞态路径检查有一致策略。
- [ ] EXEC-05：执行记录 planned、approved、started、succeeded、failed、cancelled、unknown；中断后结果未知不能自动解释为“没有执行”。
- [ ] EXEC-06：幂等重试策略和执行 ID；可控文件操作支持去重，shell/MCP/外部发布等未知副作用要求核查，不能盲目重放。
- [ ] EXEC-07：shell 取消/超时终止整个进程树，处理后台进程、管道、输出上限和清理；显式区分受管理后台任务与意外残留。
- [ ] EXEC-08：审批绑定确切执行参数、工作区和修订；审批时状态变化则重评，权限降级和取消能结束等待；审批结果持久化可审计。
- [ ] EXEC-09：主/子 Agent、内置工具、MCP、ACP 统一权限判定；授权继承取交集，子任务不能扩大权限；沙箱内外能力差异明确。
- [ ] EXEC-10：沙箱 require 失败关闭，auto 的降级可见；网络策略、密钥路径、环境变量和文件路径规则不因入口不同而失效。
- [ ] EXEC-11：日志、trace、导出及错误信息做适度敏感值脱敏；外部网页、仓库文件、工具输出和模型内容的信任来源明确，不能自动获得执行授权。
- [ ] EXEC-12：网络获取校验重定向、地址范围、响应体积、类型与超时；远程服务模式限制内部地址访问，合法本地 MCP/开发服务通过显式策略允许。
- [ ] EXEC-13：权限明确资源范围、单次/本任务有效期与撤销方式；审计记录实际授权来源，恢复不能扩大或延长授权。
- [ ] EXEC-14：受管理命令的并发、输出、运行时长及可用平台上的 CPU/内存限制可配置；不支持的限制明确显示，不冒充已隔离。

验收：同文件并行编辑、用户中途编辑、审批过期、权限收紧、取消 shell 后代、MCP 未知副作用、路径竞态和恶意工具文本都有定向测试；确保安全策略不只存在于提示词。

## v0.6：持久化恢复与工作区变更治理

范围：补强已有 JSONL、SQLite、checkpoint、worktree、diff/hunk 和合并能力。

- [ ] REC-01：事件包络、检查点和 SQLite 具有独立版本与迁移策略；旧日志兼容、未知版本、部分损坏和迁移失败的处理可诊断。
- [ ] REC-02：定义日志追加、状态检查点、索引更新的提交顺序及落盘策略；尾部半条记录可识别，索引从日志幂等重建。
- [ ] REC-03：真实进程崩溃/重启恢复，区分模型窗口快照、任务状态快照与执行结果记录；恢复不依赖 GUI 内存。
- [ ] REC-04：恢复进行中的工具/审批/子任务时重新核查；标记 unknown 的操作要求核对实际副作用，不重复自动执行。
- [ ] REC-05：每项任务捕获工作区基线，包括 tracked、untracked 和用户已有修改；使用文件指纹辨识任务与用户后续修改。
- [ ] REC-06：变更按 Task/Run/Agent/Tool 归属，支持文件/hunk 审查、选择性应用、冲突预览和验收后集成。
- [ ] REC-07：文件级撤销和任务级受保护回退，应用前校验基线；保留用户后续编辑。外部服务和任意 shell 副作用不承诺通用撤销。
- [ ] REC-08：worktree 生命周期、未合并产物、备份、清理与恢复统一管理；不自动删除尚未审阅的成果。
- [ ] REC-09：checkpoint/日志膨胀控制、保留策略、归档、备份恢复、索引修复和完整性诊断；清理前明确数据范围。
- [ ] REC-10：fork 明确哪些来源、任务状态和文件基线被继承；导入/导出包含版本和来源，剥离密钥，不默认携带可执行授权。
- [ ] REC-11：同一会话被多个进程打开时使用单写入者锁/租约或明确拒绝，防止 seq、日志与索引相互覆盖。

验收：独立进程中分别在日志写入、工具执行、审批等待和集成过程中强制中断；重启后已完成结果不重复执行、未知结果可见、用户修改不丢失；迁移支持已声明的历史版本。

## v0.7：代码理解、编辑与验证闭环

范围：提升真实仓库中的编码效率，避免靠扩大上下文窗口解决所有问题。

- [ ] CODE-01：高效文件与内容搜索，支持 ignore、glob、范围、分页和明确截断；优先利用现有本地能力，不强制增加向量数据库。
- [ ] CODE-02：有界仓库概览、目录/模块/入口映射和相关文件选择；缓存按文件变化失效，按需读取而非全仓塞入 prompt。
- [ ] CODE-03：按需接入语言服务：符号定义、引用、诊断、类型与重命名预览；语言服务不可用时回退有提示，先覆盖实际使用的语言。
- [ ] CODE-04：补强精确编辑/patch 的多文件预览、版本检查和失败边界；语法化编辑仅在有可靠解析器和真实需求时引入。
- [ ] CODE-05：识别仓库已有测试、类型检查、lint 和构建命令；尊重 AGENTS、包管理器和用户测试范围，不擅自全量验证或安装依赖。
- [ ] CODE-06：结构化诊断关联文件、行号、命令、退出状态和工作区指纹；长输出作为可检索产物保存。
- [ ] CODE-07：有界“实现→验证→诊断→修复”循环，达到次数/预算上限则保留失败证据；禁止通过删除测试、放宽断言或隐藏错误伪造成功。
- [ ] CODE-08：相关变更触发最小验证，已经有效的验证不无条件重跑；无法验证和未执行项明确展示。
- [ ] CODE-09：支持按目录继承的项目指令、优先级和来源展示；指令过大明确提示省略，不能静默丢失关键规则。
- [ ] CODE-10：Skills、prompt 模板与斜杠命令有选择、版本、来源、输入校验和预算策略；只加载相关内容，避免重复注入。
- [ ] CODE-11：任务结束生成可核查交付记录：问题、修改、diff、验证、剩余风险与未执行项；给出真实文件/产物引用。

验收：用固定真实仓库任务覆盖跨文件修改、测试失败修复、旧验证失效、目录指令和大日志。记录成功率、无关修改、耗时、调用数及费用；新能力必须与冻结基线比较。

## v0.8：多 Agent 可控协作

范围：补强现有 single/parallel/chain/race 与 worktree，不增加没有需求的新模式数量。

- [ ] AGENT-01：委派契约包含目标、输入范围、工作区、读写权限、产物、验收条件、预算与截止条件。
- [ ] AGENT-02：每个子任务与角色拥有明确职责；上下文只投影必要事实和产物引用，避免整份父历史复制。
- [ ] AGENT-03：父任务、子任务、依赖、执行尝试和结果稳定关联；结果包含修改、验证、失败与限制，不能只返回自由文本“完成”。
- [ ] AGENT-04：总预算/并发公平性/优先级统一调度，避免排队占用无限资源、饥饿、锁等待和递归委派失控。
- [ ] AGENT-05：依赖图支持已有 chain 的失败、跳过和部分结果语义；有真实工作流后再开放更复杂的 DAG 表达。
- [ ] AGENT-06：race 的胜出、失败及其他参与者停止策略明确；不同候选分支的修改隔离，不能让未采用候选继续写共享工作区。
- [ ] AGENT-07：默认将并行研究与并行修改分开；共享工作区需冲突治理，隔离工作区的集成必须先预览、再验证。
- [ ] AGENT-08：父 Agent 独立核验子任务结果、worktree diff 和测试凭据；评审 Agent 的文字认可不直接替代确定性检查。
- [ ] AGENT-09：取消、恢复、失败重试保留 Agent 树和产物归属；明确进程重启后是恢复子执行还是重建尝试。
- [ ] AGENT-10：角色能力配置可追溯，支持只读研究/实现/评审的最小模板；角色名称不能成为权限依据。

验收：覆盖两个 Agent 同文件修改、一个子任务超限、父任务取消、race 残留、子任务假成功和合并后验证失败；测量并行相对单 Agent 的实际收益，不能只以 Agent 数量证明改善。

## v0.9：Provider 与互操作契约

模块：Provider 适配保持能力接缝；按实际复杂度拆 `providers/`、`mcp/`、`acp/`，不恢复投机式运行时容器。

- [ ] INT-01：Provider 能力描述：输入/输出窗口、工具、流式、图像、结构化输出、取消、usage/缓存等；不支持的能力在请求前明确拒绝或显式降级。
- [ ] INT-02：统一 stop/error/partial/tool_call/usage 语义；模型切换重新校验工具、上下文预算和历史兼容性，不能继续用旧 usage 校准。
- [ ] INT-03：补强现有 OpenAI-compatible 适配；按真实使用顺序加入 Responses、Anthropic、Gemini 或本地模型适配，分别声明支持范围，不能仅换 URL 就声称兼容。
- [ ] INT-04：已配置 MCP 连接的断连、超时、取消、close、重连、工具列表变化和命名冲突处理；重连不自动重试未知副作用。运行时新增/移除服务器配置的热插拔留给 EXT-02。
- [ ] INT-05：MCP 支持的 tools/resources/prompts 能力显式协商，结果类型、错误和体积限制一致；外部工具安全属性仅作声明，不能代替权限策略。
- [ ] INT-06：ACP 的会话、能力协商、审批、编辑器文件系统、取消和版本兼容有契约测试；多会话不串状态。
- [ ] INT-07：配置有 schema、作用域、优先级、来源与错误定位；CLI/Server/GUI 的默认行为一致且可解释，凭证只引用安全配置。
- [ ] INT-08：Hooks/扩展点从明确事件和策略回调开始，定义失败/超时/权限边界；只有真实动态装卸需求才引入运行时生命周期。
- [ ] INT-09：为每个宣称支持的 Provider/MCP/ACP 组合提供协议夹具与有限真实互操作验证；未验证组合标为实验性。
- [ ] INT-10：补齐 ACP 的会话 load/resume、mode/model 同步和重连恢复；图片等输入按协商能力启用，当前明确不支持的能力不能假装可用。
- [ ] INT-11：MCP 结构化结果、资源引用、文本/图像结果的保留与读取策略明确，不能让资源占位符伪装成已读取内容。
- [ ] INT-12：价格配置记录来源、时间和版本，支持明确覆盖；未知或过期价格提示估算限制，历史费用不因新价格回溯变更。

验收：所有已声明组合跑取消、异常、输出限制、权限和恢复契约；至少两种实际模型配置进入候选回归。适配功能可拆多个补丁交付，未完成的 Provider 不进入支持矩阵。

范围约束：INT-03 中新增协议适配按需求选择，不要求 v1.0 一次支持全部服务商；MCP resources/prompts 和多模态也先声明支持子集。至少两种模型配置不等于必须增加两个协议栈。

## v0.10：大会话性能与日常使用体验

范围：补强已有 trace、replay、inspector、diff 和用量面板。

- [ ] UX-01：SSE 使用稳定事件游标、断线续传、去重、顺序和缺口检测；跨 Agent 的游标不能只使用局部 seq。
- [ ] UX-02：会话/事件分页、按需加载、虚拟列表和增量派生，避免每个 delta 重算全历史与整棵 Agent 树。
- [ ] UX-03：日志写入和 SQLite 更新做有界合并/事务，处理慢磁盘、背压和优雅退出；明确吞吐与持久性之间的策略。
- [ ] UX-04：大输出独立存储、按范围读取、搜索和跳转，trace 展示引用而非重复嵌入所有内容。
- [ ] UX-05：慢 SSE 消费者、断开的客户端和大量会话有资源上限；UI 断开不意味着任务自动取消，状态语义一致。
- [ ] UX-06：任务面板展示计划、有效约束、完成依据、待办、失败、审批和当前执行者；支持停止、恢复与范围明确的重试。
- [ ] UX-07：上下文检查器解释预算分配、状态来源、保留/省略、摘要回退和冲突，能从事实追溯到原始事件。
- [ ] UX-08：预算面板区分预留/实际/未知，按任务、Agent、模型与用途筛选；展示延迟、错误、重试和缓存，不将未知显示为零。
- [ ] UX-09：变更审阅关联任务与验证，批量应用前展示冲突和基线变化；审批差异预览与实际执行内容一致。
- [ ] UX-10：CLI 非 TTY 输出、退出码、机器可读模式、键盘操作、可访问性、国际化和诊断信息完善；新用户能看懂默认权限和沙箱状态。
- [ ] UX-11：会话切换、浏览器刷新、并发窗口、长时离线再连接和模型切换保持状态正确；附件体积、类型、失败和引用生命周期明确。
- [ ] UX-12：运行诊断与可脱敏导出，明确文件、任务、模型和版本；用户可选择保留/清理数据，无默认外传遥测。

验收：冻结小/大日志样本，测量首屏、追加事件、滚动、恢复、内存、磁盘和写入吞吐；实施前写入性能预算并与基线比较。慢消费者和断线恢复不能丢事件或无限增长队列。

## v0.11：支持矩阵、评测与发布候选

范围：整合持续建设的门槛，不在此时才首次增加测试。

- [ ] REL-01：明确支持的 macOS/Linux 架构、Bun 版本、模型、协议和沙箱能力；Windows 另行立项，不能默认承诺支持。
- [ ] REL-02：CI 固定受支持运行时，使用冻结 lockfile；加入 macOS 与 Linux 的关键集成路径。沙箱用例跳过必须可见，不能算作平台能力已验证。
- [ ] REL-03：形成真实仓库任务集：修 bug、跨文件重构、测试修复、恢复、并行合并和指令纠正；冻结任务、环境、评分与未见样本。
- [ ] REL-04：确定性安全/状态不变量、mock 链路、真实模型冒烟、人工审查各自报告；LLM judge 校准，不能代替确定性事实检查。
- [ ] REL-05：长任务、多次压缩、进程崩溃、网络超时、取消、磁盘失败和资源释放的故障注入；执行结果未知纳入验收。
- [ ] REL-06：同时记录任务通过、严重约束违反、非预期副作用、重复操作、恢复一致性、耗时、费用和结果不确定性；不只报告总体成功率。
- [ ] REL-07：每版与冻结基线比较；关键不变量失败禁止发布；质量阈值和成本/时延上限先写进 spec，不能看完结果再放宽。
- [ ] REL-08：二进制、校验和、安装、卸载、升级、版本回退、空环境启动与无凭证帮助命令验证；GUI/Server/CLI 版本匹配可诊断。
- [ ] REL-09：事件/API/存储兼容范围、迁移备份和回退限制写明；破坏性变更有迁移说明与版本策略，不静默改变公共响应。
- [ ] REL-10：文档与真实默认值同步，提供最小使用、权限/沙箱、恢复排错、扩展开发和贡献指南；无效示例/链接纳入文档检查。
- [ ] REL-11：依赖和发布来源、许可证、凭证扫描及构建产物检查；保持运行时依赖最小化，新增依赖需明确收益和成本。

验收：支持矩阵中的关键路径都有证据；真实模型评测具有任务/种子/模型配置/代码版本/费用口径；发布候选在干净环境可安装、执行任务、停止、恢复及卸载。

## v1.0：发布门槛

v1.0 不承诺任意任务全自动成功，承诺支持范围内的行为、状态与失败边界可信。

- [ ] GATE-01：所有候选版本的必需验收完成，已知 P0 为零；未完成扩展从支持范围中明确移出。
- [ ] GATE-02：确定性关键场景中，约束不丢失、非法状态不发生、未知结果不伪装成功、权限不越权、用户修改不丢失。
- [ ] GATE-03：冻结的长任务覆盖至少 10 次上下文压缩、用户中途纠正、两层子任务和恢复；至少三次重复运行，逐项报告关键不变量和失败。
- [ ] GATE-04：主/子/摘要/重试共享预算，停止终结受管理的进程树及后代执行；未确认的外部副作用显式标为未知。
- [ ] GATE-05：真实进程重启后任务状态与日志可重建；已有副作用不自动重复；文件级受保护撤销和冲突检测可用。
- [ ] GATE-06：交付包含真实 diff、产物和验证记录；测试未运行、失败或过期时，不能显示为已验证完成。
- [ ] GATE-07：至少两种已声明模型配置及 macOS/Linux 关键路径完成验证；质量、性能和费用符合事前冻结的门槛。
- [ ] GATE-08：CLI/GUI 能解释失败、审批、预算和恢复状态，具备迁移、安装、排错和数据保留说明。

## v1.1+：完整扩展清单与进入条件

以下优化保留在计划中，但不是 v1.0 的先决条件。每组先写独立 spec，再决定具体次版本；不能把“已列入计划”算作已承诺支持。

### MEM：跨会话长期记忆（优先候选 v1.1）

- [ ] MEM-01：用户显式保存项目偏好、已确认决策和稳定约束；支持查看、修订、删除与关闭。
- [ ] MEM-02：按项目/用户/来源隔离，记录更新时间、适用范围、冲突和失效条件；旧记忆不覆盖当前明确指令。
- [ ] MEM-03：只检索相关片段、按预算注入，避免把所有历史永久放进 prompt；检索收益通过留出任务验证。
- [ ] MEM-04：敏感信息策略、保留/导出/删除和来源可追溯；不自动跨项目共享、不默认上传云端。

进入条件：v0.3 的任务状态、v0.6 的存储治理与 v1.0 隐私边界稳定。向量索引仅在现有检索不足且实验有收益时引入。

### FLOW：可恢复后台工作流（优先候选 v1.2）

- [ ] FLOW-01：持久任务队列、依赖、暂停/恢复、去重、重试上限与定时触发。
- [ ] FLOW-02：监控任务状态变化后唤醒，而非无界轮询；通知仅在结果、失败或需要用户操作时触发。
- [ ] FLOW-03：进程重启后重建排程，避免同一任务多次运行；租约、并发与预算随任务恢复。
- [ ] FLOW-04：受管理后台命令和长测试有日志、所有者、资源限制和显式终止方式。
- [ ] FLOW-05：用户批准后才进行 Git 提交/推送、PR、发布、部署等外部写入，重启不恢复已经失效的授权。

进入条件：预算、执行幂等、崩溃恢复和通知语义已通过验证；已有 autorun 继续支持简单本地队列。

### EXT：扩展生态与更多平台（需求驱动）

- [ ] EXT-01：受支持 Hooks、工具和角色扩展的开发模板、兼容测试及版本声明。
- [ ] EXT-02：MCP 进程热插拔/工具撤回仅在真实消费者需要时实现；必要时再评估生命周期容器。
- [ ] EXT-03：插件来源校验、权限声明、安装/升级/卸载与失效隔离；插件市场独立评估，不与工具接缝绑定。
- [ ] EXT-04：更多编辑器、Provider、语言服务和离线模型按需求扩展支持矩阵。
- [ ] EXT-05：Windows、更多 CPU 架构和远程开发环境分别验证 shell、路径、进程与沙箱语义。
- [ ] EXT-06：图像/截图/浏览器工具的多模态理解、附件引用与预算专项评测；录入图像字节不等于视觉能力已验证。

### TEAM：远程协作与团队服务（独立产品方向，候选 v2.x）

- [ ] TEAM-01：用户/项目身份、RBAC、配额、审计、凭证管理和管理界面。
- [ ] TEAM-02：真正的多租户工作区、执行进程、存储、网络和密钥隔离；本地路径检查不能复用为租户安全边界。
- [ ] TEAM-03：远程 worker、任务租约、分布式调度、故障转移与产物传输；先有负载证据再引入队列基础设施。
- [ ] TEAM-04：团队审批、共享项目策略、通知与协作审查；防止授权跨用户/跨项目复用。
- [ ] TEAM-05：服务容量、运维指标、备份演练、升级窗口、配额与安全事件响应。
- [ ] TEAM-06：云端记忆、托管部署、计费和插件市场分别做需求/成本/安全评估，不自动纳入本地 v1.0。

## 架构边界与实施顺序

| 职责 | 所有权 | 不应承担 |
| --- | --- | --- |
| task | 目标、修订、约束、步骤、验收、证据关系 | 模型窗口裁剪、进程管理 |
| context | 输入选择、预算、压缩、模型窗口恢复 | 猜测真实完成状态、授权副作用 |
| runtime | Run/Agent 生命周期、预算、取消、期限 | 文件补丁语义、前端展示 |
| execution/permissions | 调度、执行记录、资源冲突、审批、权限 | 自由文本推断任务完成 |
| workspace/artifacts | 工作区基线、变更归属、产物、集成与撤销 | 宣称可以撤销任意外部副作用 |
| providers/protocols | 模型及 MCP/ACP 能力适配与规范化 | 业务计划、任务状态机 |
| server/store | 持久化、索引、API、SSE、迁移 | 第二套 Agent loop 或上下文算法 |
| gui/cli | 呈现状态、审批、操作与诊断 | 根据文本自行判断执行成功 |

实施主线：v0.2.2 → v0.3 → v0.4 → v0.5 → v0.6 → v0.7 → v0.8 → v0.9 → v0.10 → v0.11 → v1.0。评测、兼容、权限和最低可用界面随对应版本交付；无依赖的文档、协议夹具和性能基线可以并行准备。

每次实现先补 `specs/<编号>-<主题>/{spec,plan,tasks}.md`，冻结行为、兼容边界和可执行验收，再做最小完整增量。遵守现有目录风格、中文注释、函数不超过 50 行和用户规定的测试范围；只运行变更相关验证，CI 的合并/发布回归单独配置。版本计划本身不构成批量实现、提交、推送、部署或发布的授权。
